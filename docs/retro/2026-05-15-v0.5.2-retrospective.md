# Retrospective — v0.5.2

**Date:** 2026-05-15
**Milestone:** Networking + mTLS fixes for SSO
**PR:** #57 — merged to main
**Participants:** Claude, Codex, Copilot

## What Went Well

- Copilot caught a real correctness error: `project: platform` was wrong — all manifests use `project: shopping-cart` and the AppProject exists in the repo
- Copilot caught `v1alpha3` → `v1beta1` API version inconsistency across Istio files
- Istio mTLS root cause (cross-namespace, no sidecar) identified quickly via namespace isolation test
- DestinationRule with `DISABLE` mode resolved ArgoCD OIDC token exchange failure cleanly

## What Went Wrong

- Original fix changed `project: shopping-cart` → `project: platform` — wrong direction; should have applied the AppProject instead
- Bug spec and CHANGELOG were written based on incorrect in-cluster observation (all running apps used `platform`) without checking the repo's `argocd/projects/` directory
- `v1alpha3` used in DestinationRule while all other files in the directory used `v1beta1`

## Decisions Made

- `argocd/projects/shopping-cart.yaml` must be applied as a cluster bootstrap step — the App of Apps only watches `argocd/applications/`, not `argocd/projects/`
- DestinationRule disabling mTLS is the correct fix for cross-namespace Istio traffic to non-injected pods in dev
- Before writing bug docs, always check the repo directory structure for the artifact in question (AppProject, etc.)

## Theme

The v0.5.2 milestone fixed the remaining SSO blockers: the `shopping-cart` AppProject was never applied to the cluster (blocking the networking ArgoCD app), and Istio mTLS was blocking ArgoCD's in-cluster OIDC token exchange to Keycloak. Copilot's review caught a backwards fix in the initial commit, preventing an incorrect change from shipping.
