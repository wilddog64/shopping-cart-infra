# Retrospective — v1.4.11 (Partial: Data Layer GitOps + Keycloak MFA)

**Date:** 2026-05-29
**Milestone:** v1.4.11 partial — two shopping-cart-infra PRs
**PRs:**
- #70 fix(argocd): set data-layer prune=false — merged to main
- #71 feat(keycloak): role-based TOTP MFA for platform-admin and platform-developer — merged to main
**Participants:** Claude, Codex, Copilot

## What Went Well
- Codex implemented both specs exactly as written with zero scope creep
- CI green on both PRs without any flakes
- Copilot caught 4 real bugs in the MFA reconcile job (unguarded ID extractions + partial-failure gap in browserFlow enforcement)
- GraphQL thread resolution worked cleanly for all 4 threads

## What Went Wrong
- Spec did not include ID-guard requirements — Copilot had to catch them post-implementation
- `browserFlow` enforcement was inside `else` branch only — partial-failure scenario missed at spec time
- PR #70 had 2 Copilot comments that were noted but not yet addressed

## Process Rules Added
| Rule | Where |
|------|--------|
| Every command-substitution ID extraction must have an empty-check guard with explicit error message | Spec `## Rules` section |
| Idempotency guards must not skip unconditional state enforcement (e.g. realm binding) that should survive partial failures | Spec `## Rules` section |

## Decisions Made
- `prune: false` at Application level accepted for data tier — tradeoff: all removed resources (not just PVCs) require manual cleanup; acceptable given data layer is stable
- Role-based MFA via composite roles + conditional OTP flow chosen over realm-wide MFA to avoid breaking `order-user`/`catalog-user` logins and CI/CD automation

## Theme
Two infrastructure hardening changes landed cleanly. The data layer GitOps consolidation removes a source of drift by delegating ownership to ArgoCD. The Keycloak MFA change adds a meaningful security layer for privileged users with zero impact on automation or shopper flows. Copilot's review on the MFA PR caught four legitimate robustness gaps that the spec template should now require by default.
