## What Went Well

- Root cause traced quickly: `url: http://` in argocd-cm routed OIDC callback to Keycloak (port 80) instead of ArgoCD (port 443)
- Codex implemented the one-line fix cleanly — only the target file touched, commit message matched spec exactly
- Fix confirmed durable: `bin/acg-up` step 10f applies argocd-cm.yaml on every rebuild
- SSO tested and confirmed working in live cluster before PR was created
- Copilot re-review passed clean: no findings on second pass

## What Went Wrong

- Browser CA cert trust was a secondary blocker not caught in the spec — `sudo security add-trusted-cert` needed to be run in a real terminal (not via `!` prefix in Claude Code)
- Keycloak duplicate realm import error (`uk_orvsdmla56612eaefiq6wl5oi`) identified as separate idempotency bug — needs its own spec

## Theme

This milestone fixed a one-character bug (`http` → `https` in argocd-cm) that silently routed the OIDC callback to the wrong service. The fix itself was trivial; the value was in the spec-first workflow that made the fix durable and reviewable. Secondary finding: browser CA trust is a setup step that belongs in the cluster bring-up docs.
